# 约束、视图与存储过程

## 一、约束（P66~P73）

约束是保证数据完整性和一致性的规则。

### 1.1 六大约束

| 约束 | 关键字 | 说明 |
|---|---|---|
| **非空** | `NOT NULL` | 该列不能为空 |
| **唯一** | `UNIQUE` | 该列不能重复（允许多个 NULL） |
| **主键** | `PRIMARY KEY` | 非空 + 唯一，每表只能一个 |
| **外键** | `FOREIGN KEY` | 引用另一张表的主键 |
| **检查** | `CHECK` | 限制列的取值范围（MySQL 8.0+ 支持） |
| **默认值** | `DEFAULT` | 未赋值时使用默认值 |

### 1.2 建表时添加约束

```sql
CREATE TABLE employees (
  id INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(50) NOT NULL,
  email VARCHAR(100) UNIQUE,
  age INT CHECK (age >= 18 AND age <= 65),
  gender CHAR(1) DEFAULT 'M',
  dept_id INT,
  FOREIGN KEY (dept_id) REFERENCES departments(id)
);
```

### 1.3 联合约束

```sql
-- 联合主键
PRIMARY KEY (student_id, course_id)

-- 联合唯一
UNIQUE (first_name, last_name)
```

### 1.4 修改约束

```sql
-- 添加主键
ALTER TABLE employees ADD PRIMARY KEY (id);

-- 添加外键
ALTER TABLE employees ADD FOREIGN KEY (dept_id) REFERENCES departments(id);

-- 删除约束
ALTER TABLE employees DROP PRIMARY KEY;
ALTER TABLE employees DROP FOREIGN KEY fk_dept;
ALTER TABLE employees DROP INDEX idx_email;
```

### 1.5 主键 vs 外键（面试常问）

| 对比 | 主键 | 外键 |
|---|---|---|
| 作用 | 唯一标识每行 | 建立表间关联 |
| 唯一性 | 必须唯一 | 可重复 |
| 空值 | 不允许 | 允许 NULL |
| 数量 | 每表一个 | 可有多个 |

## 二、视图（P74~P77）

视图是**虚拟表**，不存储数据，只保存查询逻辑。

### 2.1 创建和使用视图

```sql
-- 创建视图
CREATE VIEW v_emp_salary AS
SELECT department_id, AVG(salary) avg_sal, COUNT(*) emp_count
FROM employees
GROUP BY department_id;

-- 使用视图（像普通表一样查询）
SELECT * FROM v_emp_salary WHERE avg_sal > 8000;

-- 修改视图
CREATE OR REPLACE VIEW v_emp_salary AS ...;

-- 删除视图
DROP VIEW IF EXISTS v_emp_salary;
```

### 2.2 视图的作用

| 作用 | 说明 |
|---|---|
| **简化查询** | 封装复杂 SQL，直接查视图 |
| **权限控制** | 只暴露部分列给用户 |
| **数据独立** | 表结构变化时修改视图定义即可 |

### 2.3 视图的可更新性

```sql
-- 简单视图可以增删改（基于单表、无聚合函数、无 GROUP BY）
-- 复杂视图通常只读
```

## 三、存储过程与函数（P78~P82）

### 3.1 存储过程

```sql
-- 创建存储过程
DELIMITER //
CREATE PROCEDURE sp_get_emp_by_dept(IN dept_id INT)
BEGIN
  SELECT * FROM employees WHERE department_id = dept_id;
END //
DELIMITER ;

-- 调用
CALL sp_get_emp_by_dept(10);
```

### 3.2 参数类型

| 类型 | 说明 |
|---|---|
| `IN` | 输入参数（默认），只传入 |
| `OUT` | 输出参数，存储过程内部赋值后返回 |
| `INOUT` | 既传入又传出 |

```sql
-- 带 OUT 参数
DELIMITER //
CREATE PROCEDURE sp_get_count(IN dept_id INT, OUT emp_count INT)
BEGIN
  SELECT COUNT(*) INTO emp_count
  FROM employees WHERE department_id = dept_id;
END //
DELIMITER ;

-- 调用
CALL sp_get_count(10, @count);
SELECT @count;
```

### 3.3 存储过程 vs 函数

| 对比 | 存储过程 | 函数 |
|---|---|---|
| 返回值 | 可以没有（用 OUT 参数） | 必须有 RETURN |
| 调用方式 | `CALL proc()` | `SELECT func()` |
| 使用场景 | 批量操作、复杂逻辑 | 计算并返回一个值 |

### 3.4 互联网公司的态度

> 阿里开发手册：**禁止使用存储过程**。理由：调试困难、移植性差、占用数据库资源、版本管理难。业务逻辑应放在应用层。

## 四、容易出错的地方

1. **外键约束**：删除被引用的表会报错，要先删外键约束
2. **视图不是表**：视图不存储数据，查视图实际是执行底层 SQL
3. **存储过程调试**：MySQL 存储过程调试很不方便
4. **CHECK 约束**：MySQL 5.7 不支持，8.0 才支持
