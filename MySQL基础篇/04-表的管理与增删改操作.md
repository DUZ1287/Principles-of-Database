# 表的管理与增删改操作

## 一、DDL——表结构管理（P49~P58）

### 1.1 创建表

```sql
CREATE TABLE employees (
  employee_id INT PRIMARY KEY AUTO_INCREMENT,
  first_name VARCHAR(50) NOT NULL,
  last_name VARCHAR(50) NOT NULL,
  email VARCHAR(100) UNIQUE,
  salary DECIMAL(10,2) DEFAULT 0.00,
  hire_date DATE,
  department_id INT,
  FOREIGN KEY (department_id) REFERENCES departments(department_id)
);
```

### 1.2 修改表结构

```sql
-- 添加列
ALTER TABLE employees ADD phone VARCHAR(20);

-- 修改列类型
ALTER TABLE employees MODIFY phone VARCHAR(30);

-- 修改列名
ALTER TABLE employees CHANGE phone mobile VARCHAR(30);

-- 删除列
ALTER TABLE employees DROP mobile;

-- 重命名表
ALTER TABLE employees RENAME TO staff;
-- 或
RENAME TABLE employees TO staff;

-- 删除表
DROP TABLE IF EXISTS employees;

-- 清空表（保留结构）
TRUNCATE TABLE employees;
```

### 1.3 DROP vs DELETE vs TRUNCATE（经典面试题）

| 对比 | DROP | TRUNCATE | DELETE |
|---|---|---|---|
| 表结构 | 删除 | 保留 | 保留 |
| 数据 | 全删 | 全删 | 可条件删 |
| 自增重置 | — | 重置为 1 | 不重置 |
| 触发器 | 不触发 | 不触发 | 触发 |
| 回滚 | 不能 | 不能 | 能 |
| 速度 | 最快 | 次快 | 最慢 |

## 二、DML——数据增删改（P49~P58）

### 2.1 INSERT

```sql
-- 基本插入
INSERT INTO employees (first_name, last_name, salary)
VALUES ('张', '三', 8000);

-- 批量插入
INSERT INTO employees (first_name, salary)
VALUES ('李四', 9000), ('王五', 10000);

-- 将查询结果插入
INSERT INTO emp_backup (name, salary)
SELECT first_name, salary FROM employees WHERE department_id = 10;
```

### 2.2 UPDATE

```sql
-- 更新单列
UPDATE employees SET salary = 9000 WHERE employee_id = 100;

-- 更新多列
UPDATE employees SET salary = salary * 1.1, commission_pct = 0.1
WHERE department_id = 20;
```

### 2.3 DELETE

```sql
-- 条件删除
DELETE FROM employees WHERE employee_id = 100;

-- 清空全部数据
DELETE FROM employees;  -- 逐行删除，可回滚
TRUNCATE TABLE employees;  -- 直接清空，不可回滚，更快
```

## 三、数据类型精讲（P59~P65）

### 3.1 整数类型

| 类型 | 字节 | 范围 |
|---|---|---|
| TINYINT | 1 | -128 ~ 127 |
| SMALLINT | 2 | -32768 ~ 32767 |
| MEDIUMINT | 3 | -8388608 ~ 8388607 |
| **INT** | 4 | -21亿 ~ 21亿 |
| BIGINT | 8 | 极大 |

### 3.2 浮点与定点

| 类型 | 说明 | 适用场景 |
|---|---|---|
| FLOAT | 4 字节，近似值 | 精度要求不高 |
| DOUBLE | 8 字节，近似值 | 科学计算 |
| **DECIMAL(M,D)** | 精确值 | **金额、价格必须用** |

> 金额计算**必须用 DECIMAL**，FLOAT/DOUBLE 有精度误差（0.1+0.2≠0.3）。

### 3.3 字符串类型

| 类型 | 说明 | 适用场景 |
|---|---|---|
| **VARCHAR(M)** | 可变长度，M 为最大字符数 | 姓名、邮箱、地址 |
| CHAR(M) | 固定长度 | 手机号、身份证号 |
| TEXT | 大文本 | 文章内容、备注 |
| BLOB | 二进制大对象 | 图片、文件 |

> VARCHAR 和 CHAR 的选择：长度变化大用 VARCHAR，长度固定用 CHAR（如 MD5 值）。

### 3.4 日期类型

| 类型 | 格式 | 说明 |
|---|---|---|
| **DATE** | YYYY-MM-DD | 日期 |
| **TIME** | HH:MM:SS | 时间 |
| **DATETIME** | YYYY-MM-DD HH:MM:SS | 日期时间（1000~9999年） |
| **TIMESTAMP** | YYYY-MM-DD HH:MM:SS | 时间戳（1970~2038年，自动更新） |
| YEAR | YYYY | 年份 |

> DATETIME vs TIMESTAMP：TIMESTAMP 占 4 字节、自动转换时区、有 2038 年限制；DATETIME 占 8 字节、范围更大。**推荐 DATETIME**。

---

## 四、容易出错的地方

1. **DECIMAL vs FLOAT**：金额必须用 DECIMAL
2. **VARCHAR 长度**：`VARCHAR(255)` 和 `VARCHAR(256)` 存储不同（长度标识 1 字节 vs 2 字节）
3. **DELETE 不加 WHERE**：会删除所有数据！
4. **TRUNCATE 不能回滚**：比 DELETE 快但不可恢复
5. **TIMESTAMP 的 2038 问题**：4 字节时间戳有范围限制
