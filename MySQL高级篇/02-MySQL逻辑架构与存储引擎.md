# MySQL逻辑架构与存储引擎

## 一、这个知识点是什么

理解 MySQL 内部是怎么工作的——一条 SQL 从发送到返回结果经历了哪些步骤，以及数据在磁盘上是怎么存储的（存储引擎）。

## 二、为什么要学它

- 面试必问："一条 SQL 在 MySQL 中的执行流程"
- 理解执行流程才能理解为什么有些查询快、有些慢
- 存储引擎的选择直接影响事务、锁、性能

---

## 三、核心内容

### 3.1 MySQL 逻辑架构（P109）

**MySQL 三层架构**：

```
┌─────────────────────────────────────┐
│         连接层（Connection Pool）    │  ← 管理连接、认证、线程池
├─────────────────────────────────────┤
│         服务层（Server Layer）       │  ← SQL 解析、优化器、缓存
│  ┌────────┬──────────┬──────────┐  │
│  │ SQL接口 │ 解析器    │ 优化器   │  │
│  └────────┴──────────┴──────────┘  │
│              ┌──────────┐          │
│              │ 查询缓存  │          │  ← MySQL 8.0 已移除
│              └──────────┘          │
├─────────────────────────────────────┤
│         存储引擎层（Engine Layer）   │  ← InnoDB / MyISAM 等
└─────────────────────────────────────┘
```

**各层职责**：

| 层级 | 职责 | 关键组件 |
|---|---|---|
| **连接层** | 管理客户端连接、线程池、认证 | Connection Pool、Thread Pool |
| **服务层** | SQL 解析、优化、执行 | Parser、Optimizer、Cache |
| **引擎层** | 数据的实际存取 | InnoDB、MyISAM、Memory 等 |

### 3.2 SQL 执行流程（P110~P111）

**一条 SQL 的完整旅程**：

```
1. 客户端发送 SQL → 连接层接收
2. 查询缓存检查（MySQL 5.7，8.0 已移除）→ 命中直接返回
3. 解析器（Parser）：SQL 文本 → 解析树（语法检查）
4. 预处理器：语义检查（表/列是否存在、权限检查）
5. 优化器（Optimizer）：生成执行计划（选索引、定 JOIN 顺序）
6. 执行器（Executor）：调用存储引擎 API 执行
7. 存储引擎读写数据 → 返回结果
8. 返回结果给客户端
```

**MySQL 8.0 vs 5.7 的变化**：

| 变化点 | MySQL 5.7 | MySQL 8.0 |
|---|---|---|
| 查询缓存 | 有 | **已移除** |
| 角色管理 | 无 | 有 |
| 窗口函数 | 无 | 有 |
| CTE | 无 | 有 |
| 降序索引 | 声明但无效 | 真正支持 |
| 隐藏索引 | 无 | 有 |

### 3.3 缓冲池 Buffer Pool（P112）

**Buffer Pool** 是 InnoDB 的核心组件——一块内存区域，缓存磁盘上的表数据和索引。

```
磁盘（ibd 文件） ←→ Buffer Pool（内存） ←→ SQL 查询
```

| 组件 | 作用 |
|---|---|
| **Buffer Pool** | 缓存数据页和索引页，减少磁盘 IO |
| **Change Buffer** | 缓存对非唯一索引的修改 |
| **Adaptive Hash Index** | 自适应哈希索引，加速等值查询 |
| **Log Buffer** | 缓存 Redo 日志，等待刷盘 |

> **关键数字**：内存访问速度是磁盘的 10000 倍以上，Buffer Pool 越大查询越快。通常设为物理内存的 50%~75%。

### 3.4 存储引擎（P113~P114）

#### InnoDB vs MyISAM 深度对比

| 对比维度 | InnoDB | MyISAM |
|---|---|---|
| **事务** | 支持（ACID） | 不支持 |
| **外键** | 支持 | 不支持 |
| **行锁** | 支持（高并发） | 只有表锁 |
| **MVCC** | 支持 | 不支持 |
| **崩溃恢复** | 自动恢复 | 容易损坏 |
| **COUNT(*)** | 需逐行扫描 | 有计数器（快但不准） |
| **全文索引** | MySQL 5.6+ 支持 | 原生支持 |
| **并发能力** | 高 | 低 |

> **结论**：现代 MySQL 生产环境**几乎 100% 使用 InnoDB**，MyISAM 已基本退出历史舞台。

#### 其他存储引擎

| 引擎 | 核心特点 | 典型场景 |
|---|---|---|
| **MEMORY** | 数据存内存，断电丢失 | 临时表、热点数据缓存 |
| **ARCHIVE** | 高压缩、只支持 INSERT/SELECT | 日志归档、历史数据 |
| **CSV** | 文本格式、无索引 | 数据导入导出 |

## 四、容易出错的地方

1. **查询缓存**：MySQL 8.0 已移除，面试不要说"用查询缓存优化"
2. **InnoDB 的 COUNT(*)**：需要遍历，比 MyISAM 慢，但准确
3. **Buffer Pool 大小**：不是越大越好，要留内存给操作系统和其他进程
4. **存储引擎选择**：除非特殊需求，一律用 InnoDB

| 关联知识 | 关系 |
|---|---|
| 索引原理 | 索引结构由存储引擎决定 |
| 事务 ACID | 只有 InnoDB 支持事务 |
| 锁机制 | 行锁只有 InnoDB 支持 |
| Buffer Pool | 影响性能调优的关键参数 |

## 七、总结

- MySQL 三层架构：连接层→服务层→引擎层
- SQL 执行流程：缓存→解析→优化→执行
- 生产环境统一使用 InnoDB
- Buffer Pool 是 InnoDB 性能的核心

## AI辅助思考

### 这个知识点真正重要的地方

"SQL 执行流程"是面试**几乎必问**的题目，回答时要能清晰说出：解析→预处理→优化→执行 这几个步骤。InnoDB vs MyISAM 的对比也是高频题，重点记住：InnoDB 支持事务、行锁、MVCC、崩溃恢复。

### 和哪些知识点有关

- **执行流程** → 索引（优化器决定用哪个索引）、慢查询（哪个阶段慢）
- **Buffer Pool** → 性能调优（innodb_buffer_pool_size 参数）
- **存储引擎** → 事务、锁、MVCC 都依赖 InnoDB

### 初学者容易误解什么

1. 以为所有 MySQL 都一样——不同存储引擎行为完全不同
2. 以为查询缓存能提升性能——实际上维护成本太高，MySQL 8.0 已经移除
3. 以为 Buffer Pool 设得越大越好——超过物理内存会触发 swap，反而更慢
